Critical Rendering Path (CRP) Cheat Sheet

A reference architecture diagram and performance checklist covering the browser rendering pipeline from network packet bytes to physical monitor display refreshes.

The 5 Stages of the Rendering Pipeline

Stage 1 DOM Construction (Document Object Model)
  • Input: Raw HTML byte stream from TCP socket.
  • Steps: Byte Stream → Character Encoding (UTF-8) → Tokenization → Node Emission → Tree Construction.
  • Optimization: Stream HTML responses; avoid synchronous <script> without defer or async in the <head>.
Stage 2 CSSOM Construction (CSS Object Model)
  • Input: Linked external stylesheets and inline <style> tags.
  • Characteristics: CSS is render-blocking. The browser will NOT render any pixels until the entire CSSOM is built.
  • Optimization: Inline critical above-the-fold CSS; preload heavy stylesheets with rel="preload" as="style".
Stage 3 Render Tree & Layout (Reflow)
  • Input: Merged DOM + CSSOM tree (ignoring display: none and <head>).
  • Computation: Computes the exact box coordinates, margin box, padding box, and viewport geometry.
  • Caution: Avoid JavaScript that reads geometry (e.g., offsetHeight, getBoundingClientRect()) immediately after writing CSS styles (triggers Forced Synchronous Layout).
Stage 4 Paint & Display Lists
  • Input: Visual geometry and calculated styles.
  • Computation: Records drawing commands into Skia Display Lists (fill rect, draw border, text glyphs).
  • Caution: Heavy CSS shadows, complex gradients, and extensive border radii increase paint recording time.
Stage 5 Compositing & GPU Rasterization
  • Input: Layer tree partitioned across memory tiles.
  • Execution: GPU raster threads convert vector display lists into bitmap tiles, and the Compositor thread transforms layers at 60/120Hz independently of the main JavaScript thread.
  • Smooth Animation Rule: Only animate transform and opacity. Never animate width, height, top, or left.
